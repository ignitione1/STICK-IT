# Push-уведомления

Stick-it отправляет короткие уведомления на рабочий стол при создании адресованной пользователю записки или ответа. Текст записки и имя автора в push не включаются. Сообщение отделу отправляется всем его активным участникам с действующими подписками, кроме автора; при нескольких вариантах адресации сотрудник не получает повторной отправки на одну подписку. Отметки прочтения и готовности — общие для записки, а не отдельные для каждого получателя.

## Включение

Сотрудник нажимает переключатель «Push выключены» под настройкой звука и подтверждает запрос Chrome, Edge или другого поддерживаемого браузера. Без разрешения браузера включить push автоматически нельзя. Отключение сохраняется в данном браузере для учётной записи. Подписка привязана к сессии: по её истечении или после выхода получение прекращается, при следующем входе приложение переподключает разрешённую подписку. Отзыв разрешения браузером тоже прекращает показ. Текущее назначение — desktop; мобильный сценарий отдельно не проверен.

При открытой вкладке после действия пользователя доступен локальный звук ICQ; он воспроизводится один раз, системный звук push отключён. Пока браузер блокирует звук страницы или вкладки закрыты, используется системный звук. Настройка звука по умолчанию включена и хранится отдельно для каждого аккаунта в браузере. [Подробнее о звуке](../../docs/notification-sound.md).

## Настройка сервера

Локальная команда `npm run dev:local` создаёт и сохраняет случайные VAPID-ключи в `.local/manual/push-keys.json`. На отдельном сервере задайте `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY` в защищённом окружении. Команда `npm --prefix server run push:keys` создаёт пару в `.local/push-vapid.env` и не перезаписывает существующий файл. Ключи должны сохраняться между перезапусками; при замене пользователям нужно повторно подключить подписку. Секретный ключ и URL подписок нельзя публиковать или записывать в логи.

Перед запуском API вручную примените миграции к известной базе: `0006` создаёт таблицу подписок. Для развёрнутого сайта нужен HTTPS; loopback подходит для локальной разработки. Серверу нужен исходящий HTTPS-доступ к службам браузеров; принимаются адреса FCM, Mozilla и Windows Push. Текущий SSH-туннель из [инструкции VPS](../../deploy/README.md) — тестовый HTTP-стенд, не инструкция по настройке публичного HTTPS.

## Поведение и проверка

Сервер отправляет push после сохранения новой записки или когда получатель отмечает записку выполненной. Повторный запрос на создание с тем же ID не создаёт повторную отправку. Изменения, восстановление из архива и сброс отметок не отправляют новый push. Очереди и повторных попыток доставки нет, срок жизни сообщения — пять минут. Для доставки указан высокий приоритет, но служба push, браузер, ОС, сеть и срок сессии влияют на результат; принятие сообщения push-службой не подтверждает его показ пользователю.

Синхронизация доски остаётся основанной на опросе. При активной push-подписке звук по опросу не дублируется: service worker выбирает одну вкладку для звука или оставляет звук системе. `GET /api/push/status` доступен вошедшему пользователю и возвращает число активных подписок и последний результат отправки для его аккаунта в памяти текущего процесса; он не раскрывает адреса подписок, не хранит историю и очищается при перезапуске сервера.

Проверки: `npm --prefix server test` покрывает права на подписки, ограничения адресов push-служб и адресатов; `npm run test:e2e -- tests/push.spec.ts tests/push-worker.spec.ts tests/notification-sound.spec.ts tests/department-notifications.spec.ts` проверяет интерфейс, service worker, звук и адресацию отдела. Изолированные тесты имитируют push-события; фактическую доставку через внешние push-службы и системные настройки необходимо проверять отдельно.
