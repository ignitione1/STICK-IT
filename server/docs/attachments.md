# Вложения записок

Новые записки и ответы поддерживают до 5 файлов: до 10 МиБ каждый, до 25 МиБ суммарно. В редакторе есть отдельные кнопки «Изображение» и «Файл», выбранные файлы можно убрать до отправки. Текст записки остаётся обязательным. Автор опубликованной записки может менять текст и состав вложений: удалить прежние, добавить новые или заменить файл. Закрытие редактора без сохранения не удаляет прежние файлы. Чужие записки не редактируются даже администратором.

Дубли определяются по SHA-256 содержимого, независимо от имени файла. Браузер пропускает повторы при выборе, сервер независимо отклоняет повторное содержимое при создании и редактировании. Существующие вложения с пустым хешем проверяются по исходным файлам при необходимости.

Изображения JPEG, PNG, GIF и WebP открываются в модалке с кнопкой «Скачать». Формат изображения проверяется по расширению и сигнатуре; исходные байты сохраняются без преобразования. SVG не принимается. Документы Word/Excel/PowerPoint, PDF, TXT, MD, CSV/TSV, RTF, ODT/ODS/ODP, JSON/XML/LOG и архивы ZIP/7Z/RAR скачиваются напрямую с `Content-Disposition: attachment`. Документы сервер не исполняет и не просматривает. Диалог выбора папки зависит от настройки скачивания в браузере.

## API и хранение

- `POST /api/stickers/with-attachments`: multipart, поле `draft` с тем же JSON, что у `POST /api/stickers`, и до 5 полей-файлов `files`. Обязательны сессия, Origin и CSRF. Поля автора берутся из сессии, действуют обычные ограничения создания/ответов.
- `POST /api/stickers/:id/with-attachments`: multipart для редактирования, `draft` содержит `text`, `revision`, `keepAttachmentIds`; `files` — новые файлы. Права автора проверяются до загрузки, версия — перед фиксацией транзакции.
- `PATCH /api/stickers/:id`: тот же текст/версия и необязательный `keepAttachmentIds` для удаления вложений без добавления новых. Пустой массив удаляет все; отсутствие поля сохраняет прежние вложения. ID чужого вложения отклоняется.
- `GET /api/attachments/:id/preview`: только поддерживаемые изображения, inline.
- `GET /api/attachments/:id/download`: любой поддерживаемый файл, принудительное скачивание с исходным именем.

Чтение доступно всем активным авторизованным сотрудникам, как и просмотр досок/архива; адресаты не ограничивают просмотр. Гостям и заблокированным сотрудникам файлы недоступны. Ответы имеют `Cache-Control: no-store`, `nosniff` и ограничивающий CSP. Имена файлов не используются как пути на диске; ключи генерируются сервером, оригинальное имя передаётся через UTF-8 Content-Disposition.

Файлы пишутся потоково в `UPLOAD_DIR`, в БД сохраняются только метаданные таблицы `attachments`. Миграция `0005_high_drax.sql` добавляет nullable `content_hash`, сохраняя старые файлы и метаданные. Новая записка, адресаты и метаданные всех файлов создаются одной транзакцией. Редактирование текста/вложений проверяет `revision` и фиксируется одной транзакцией; прежние файлы удаляются с диска только после её успеха. При конфликте версии или другой ошибке новые файлы удаляются, старые сохраняются. Если физическая очистка после успешного удаления не удалась, метаданные уже удалены, API не выдаёт такой файл, а сервер пишет предупреждение без исходных путей. При идемпотентном повторе создания ненужные новые файлы также удаляются до ответа клиенту. После аварийного завершения процесса могут остаться неиспользуемые файлы; автоматическая очистка таких файлов пока не реализована.

`GET /api/stickers` возвращает массив `attachments` с публичными ID, именами, размерами и типом отображения; совместимое поле `attachment` содержит первый элемент. Пути хранения и байты файлов в JSON не передаются. Архивирование сохраняет вложения. Старые демонстрационные записи могут содержать метаданные без файла — интерфейс сообщает о недоступности.

В ручном стенде файлы лежат в `.local/manual/uploads`, рядом с `.local/manual/postgres`. В Compose — в отдельном volume `/app/uploads`, который уже включён в scripts backup/restore. Требуется сохранять и БД, и этот каталог. Nginx допускает тело запроса до 26 МиБ и передаёт его потоково с `proxy_request_buffering off`, не заполняя ограниченный tmpfs. API отдельно проверяет количество, размер каждого файла и суммарный размер. Проверки в памяти и временных каталогах не заменяют проверку Linux volume, контейнерного запуска и восстановления резервных копий.
